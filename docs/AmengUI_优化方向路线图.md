# AmengUI 优化方向路线图

> 2026-08-18 讨论整理
> 核心问题：AmengUI 还有什么新优化方向？还是把剩下的交给包管理器？

---

## 一、先回答核心问题：剩下的该交给包管理器吗？

**结论：方向对，但不能"直接甩锅"。**

- 桌面环境的本职是 **shell + 集成**，不是把每个 App 都内置。让包管理器承载"功能扩展"是 KDE / GNOME 扩展生态验证过的正路，所以你的直觉没错。
- 但前提变了：你现在的 `pacman`（`com.pacman.app`）装的是 `.app`——也就是 **Windows 程序的启动器**，不是 AmengUI 自己的"扩展 / 插件"。要把功能外包出去，得先让 pacman 支持**扩展清单（manifest）**：能往 shell 注册托盘图标、控制中心分页、开始菜单分区、文件处理器。这本身是一次架构升级，不是"停止写功能"。
- **建议分工**：
  - 留在核心（不可替代的 shell 职责）：窗口管理、首次运行、认证、`passwd/shadow`、主题、Unix 路径层（amsys）。
  - 走扩展（可变 / 可选）：额外的控制中心开关、第三方工具集成、小部件、实验性功能。

---

## 二、按优先级排序的优化方向

### P0 —— 采用率阻断项（不性感，但最关键）
1. **首次运行体验**：目前 release 仍是 0 附加资产，且 `rootdir/`、`config/` 被排除出构建、需手动建目录。目标：clone → 装 → 跑不用看文档；生成 Squirrel 安装包属于可选的发布目标。
2. **崩溃自愈**：Electron shell 一崩，整个桌面就死。用 `amsys` launcher 做看门狗（watchdog），shell 退出即自动重启——这才有"真桌面环境"的体感，也是和玩具项目的分水岭。

### P1 —— 你的差异化（"Windows 上的 Unix"）
3. **真正的终端 + Unix 路径贯通（最该做的一件事）**：
   - 内置 xterm.js 终端跑 pwsh，但让 amsys 路径层拦截 `cd /home`、`ls /usr/share/applications`、`cat /etc/passwd`。
   - 加 readline 体验：历史、Tab 补全、管道。让"Unix on Windows"从**演示**变成**可用**。
   - 这点比再加十个设置页更能镇住"鄙视链"那帮人，而且它诚实——是真的 shell 能力，不是包装。
4. **环境变量 / $PATH 映射**：把 amsys 虚拟根挂进 shell 的 PATH，让 `.app` 像真实命令一样可被调用，强化"类 Unix"叙事。

### P2 —— 健壮性（还清之前的技术债）
5. **窗口置底**：从"2 秒轮询"换成 `SetWinEventHook` 监听 Z 序变化，去掉轮询开销与抖动（你已在置底上叠加了"聚焦推送"，再补事件钩子就干净了）。
6. **常驻 PowerShell 服务收敛**：audio 已迁 C# COM 互操作，其余 `sys.ps1` 之类继续往原生 / amsys 收，减少常驻进程与失败面。
7. **多显示器 / DPI / 无障碍**：Electron 有 per-monitor DPI，但 CSS 需适配；补高对比度主题、字体缩放，覆盖笔记本 + 外接屏场景。

### P3 —— 平台化（"交给包管理器"的终局）
8. **pacman 升级为扩展平台**：manifest 支持注册 tray / 控制中心页 / 开始菜单分区 / 文件关联。**之后新功能 = 写扩展，不动核心**——这才是桌面环境该有的成长曲线。
9. **自动更新闭环**：已有"检查更新"UI，确保它能真的拉 GitHub release 并走 Squirrel 更新（目前 release 无资产，这环还是断的）。

---

## 三、一句话总结

别再堆内置面板了。把核心 shell 打磨到「稳（首次运行 + 崩溃自愈）+ 真（Unix 终端贯通）」，再把 `pacman` 养成扩展平台让功能外包出去——这一步走完，AmengUI 就从"一个 Electron 壳"变成"一个能长出血肉的桌面环境框架"喵~
